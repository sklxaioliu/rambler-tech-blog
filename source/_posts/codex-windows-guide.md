## 学习目标

读完本文，你应该能够：在 Windows 上找到官方安装入口并登录；分清桌面版、命令行版和编辑器扩展；让 Codex 在指定文件夹完成一个小任务；看懂文件修改和运行结果；遇到报错时知道先检查什么。

本文按 **2026 年 10 月 22 日**可查阅的官方资料整理。产品名称、菜单、可选模型和套餐权益会调整，界面文字不完全一致时，以文末官方入口为准。这里写的是操作指南，文中的练习验收值是你需要检查的目标，不代表已经在你的电脑上替你完成安装或运行。

## 先用一个例子理解

假设你想做一个网页，里面只有一句“你好，世界”和一个按钮。

普通聊天可以告诉你“应该怎么写”；当你打开项目文件夹，并给予适当的操作权限后，Codex 可以进一步阅读文件、修改代码、调用命令，并根据报错继续调整。你仍然要判断任务是否说清楚、修改是否合理、最终效果是否符合要求。

可以把它理解为一位需要你交代任务的开发伙伴：你说“装修一下”，对方很难知道预算和风格；你说“把这个房间的墙刷成白色，保留地板，完工后检查门窗”，结果就更容易验收。

例如，把“帮我做个网站”改成：

```text
请在当前项目文件夹创建一个中文单页网站。
页面包含标题“我的学习记录”、一段介绍和一个计数按钮。
按钮每点击一次，数字加 1；重置按钮把数字变回 0。
只用 HTML、CSS、JavaScript，不安装依赖。
完成后告诉我改了哪些文件、如何打开、怎样检查按钮是否正常。
```

这段话已经说明了目标、位置、技术范围和检查方法。即使你不懂代码，也能检查“点三次是否显示 3”。

## 基础知识

### 1. 先分清三种使用入口

| 入口 | 你在哪里操作 | 更适合谁 | 是否都要安装 |
| --- | --- | --- | --- |
| 桌面客户端中的 Codex | 独立桌面窗口，选择本地项目 | 希望看文件变化、用中文交代任务的初学者 | 本文主线，先掌握这一种 |
| Codex CLI | PowerShell 等终端 | 经常用命令行、希望在项目目录工作的人 | 可选 |
| Codex 编辑器扩展 | VS Code 等受支持编辑器的侧边栏 | 已经在编辑器中写代码的人 | 可选 |

它们都是使用 Codex 的入口，并不是三个必须依次安装的软件。第一次学习，先把桌面方式走通，再考虑另外两种。

官方文档目前将桌面安装引导放在 ChatGPT 桌面应用体系中，并说明：涉及代码库和开发工具的任务，应从 ChatGPT 下拉菜单选择 **Codex**。因此，你从官方入口看到 ChatGPT 应用名称，不一定表示进入了错误页面；关键是核对官方来源，以及应用内是否提供 Codex 开发模式。旧版独立界面与新版整合界面可能不同。[官方快速入门](https://learn.chatgpt.com/docs/quickstart)

### 2. 项目文件夹是什么

项目文件夹就是某一项工作的文件放在一起的目录。例如：

```text
D:\Codex练习\hello-codex\
  index.html       网页内容
  style.css        网页样式
  script.js        按钮行为
  README.md        使用说明
```

桌面快捷方式不是项目本身，浏览器打开的网站也不等于本地源码。让 Codex 修改博客时，应打开真正存放 `_config.yml`、`package.json` 和 `source` 的博客目录，而不是随便打开桌面。

### 3. 账号登录、使用额度和 API 是不同的事

初学者优先选择“使用 ChatGPT 账号登录”。可用功能和额度由你的账号、套餐及当前产品规则决定。API Key 是另一种认证方式，API 的使用计费需要单独理解，不能把它当作“登录桌面版必须购买的密码”。[官方认证说明](https://learn.chatgpt.com/docs/auth)

例如：你能正常登录，但暂时无法继续发起任务，可能是当前使用窗口达到限制，并不说明软件坏了。先查看应用中的使用限制与恢复时间，不要反复卸载软件。

### 4. 安装应用，不等于安装所有开发环境

桌面应用、Node.js、Git 是不同的工具。写一段普通文档，不一定需要 Node.js；运行 Hexo 博客通常需要 Node.js 和 npm；记录代码版本需要 Git。只安装当前项目需要的工具即可。

比喻一下：Codex 像协作人员，Node.js 像执行某类工作的机器，Git 像修改档案柜。协作人员到了，并不表示所有机器都已经放好。

## 操作步骤

### 第一步：从官方入口安装 Windows 客户端

1. 打开 [Windows 官方安装说明](https://learn.chatgpt.com/docs/windows/windows-app)。
2. 按页面提供的官方 Microsoft Store 入口安装。核对发布者与官网链接，不要从“破解版”“无限额度版”下载。
3. 安装结束后，从开始菜单打开应用。
4. 使用你自己的账号登录；如出现验证码、二次验证，在登录页面自己完成。
5. 按官方快速入门选择 Codex 开发模式。不同版本的按钮可能位于模式下拉菜单或项目入口。

会使用终端的人，也可以按 Windows 官方文档使用以下 Store 安装命令；这是与商店入口并列的选项，不需要两个都做：

```powershell
winget install --id 9PLM9XGG6VKS -s msstore
```

如果提示找不到 `winget`，先使用官方文档中的商店入口即可。不要为了绕过一个安装问题，随意修改系统安全配置。

**完成检查：**应用能启动、账号已经登录、能够进入开发任务入口。仅看到下载页面，或者浏览器里已经登录 ChatGPT，还不能证明桌面应用完成登录。

### 第二步：准备一个独立练习目录

用资源管理器新建 `D:\Codex练习\hello-codex`。没有 D 盘就换成自己能找到的目录，例如文档文件夹下的 `Codex练习\hello-codex`。

愿意使用 PowerShell 的同学可以执行：

```powershell
New-Item -ItemType Directory -Path 'D:\Codex练习\hello-codex' -Force
Set-Location 'D:\Codex练习\hello-codex'
Get-Location
```

三行分别表示：创建目录；进入目录；显示当前位置。引号可以避免路径中空格造成误解。你在聊天里写出一个路径，并不自动意味着程序已经打开或获得访问这个目录的权限。

接着在客户端中选择“打开文件夹”或对应项目入口，选中这个目录。观察项目名称和目录位置，确认没有误选整个磁盘。

### 第三步：先让它看，再让它改

发送第一条任务：

```text
请先查看当前项目目录，告诉我里面有哪些文件，以及你当前能做哪些操作。
暂时不要修改文件，也不要安装任何依赖。
我是初学者，请用中文说明。
```

这样可以提前发现“打开了错误文件夹”或“当前任务只有聊天能力”等问题。如果回复只给你一段示例代码，却没有实际文件变化，先检查项目和任务模式，再检查权限，而不是直接认为代码已经写进电脑。

### 第四步：理解权限，不要一上来开放整个电脑

你主要需要理解两件事：**它能访问哪里、做什么**，以及 **哪些操作需要审批**。它们相关，但不是同一个开关。一个项目允许写文件，并不代表能自动访问任何网页或账号。[官方权限与安全说明](https://learn.chatgpt.com/docs/agent-approvals-security)

新手可以按这个顺序操作：

1. 先允许查看当前项目。
2. 确认任务后，允许在当前项目内修改文件。
3. 遇到安装依赖、访问网络、执行系统命令等申请时，查看具体命令和原因。
4. 对公开上传、删除目录、修改账号设置等操作，确认目标和影响。

例如，它申请运行 `npm run build`，你应检查这是当前博客目录里的构建命令；它申请删除目录，你应先确认完整路径和是否有备份。不要因为某个报错就把权限调到最大：权限扩大也不会自动安装缺失的软件，更不会自动连接你已登录的 Chrome。

### 第五步：完成第一个能验收的小项目

复制本文开头的计数器任务。还可以补充：

```text
请实际创建文件，不要只把代码贴在聊天里。
按钮要适合手机点击；数字区域要有清晰标签。
不要引用外部脚本或图片。
如能运行浏览器检查，请验证点击和重置；不能检查的项目请明确说明。
```

完成后，先看文件列表是否出现 `index.html` 等文件。如果实现是一个独立 HTML 文件，可以用浏览器打开它；如果使用多个相对引用的文件，应保持它们原来的目录关系。

按顺序验收：

| 操作 | 应观察到的结果 |
| --- | --- |
| 第一次打开页面 | 初始计数为 0 |
| 连续点击加一按钮三次 | 计数为 3 |
| 点击重置 | 计数变成 0 |
| 缩窄浏览器窗口 | 内容和按钮仍能看到，不出现明显横向溢出 |

“我已经写好了”和“已经通过检查”是两回事。让它说明用了什么检查、检查了什么、哪些没有条件验证。

### 第六步：让修改过程可回退

先用复制整个练习目录的方式做备份，也比没有备份好。正式项目推荐使用 Git。

如果电脑已安装 Git，在项目目录中可以先检查：

```powershell
git --version
git status
git diff
```

`git status` 看哪些文件发生变化；`git diff` 看已跟踪文件具体改了什么。新建且尚未跟踪的文件通常不会出现在普通 `git diff` 中，要结合文件列表和编辑器查看。空目录还没初始化 Git 时，`git status` 会提示不是仓库，这是正常提示。

对纯练习目录，你可以运行 `git init` 初始化。提交前检查文件，排除账号凭据和不该公开的资料；第一次提交如要求填写作者姓名和邮箱，按自己的情况设置，别照抄别人的身份。

### 第七步：可选——安装 Codex CLI

**只想使用桌面版的读者可以跳过本节。** CLI 是在终端里使用 Codex，并不是桌面版安装成功的前提。

这里采用官方支持的 npm 安装方式：先从 Node.js 官方渠道安装合适的 LTS 版本，重开 PowerShell，再依次检查和安装。[Codex CLI 官方说明](https://learn.chatgpt.com/docs/codex/cli)

```powershell
node --version
npm --version
npm install -g @openai/codex
codex --version
```

`--version` 是查看版本；`-g` 表示安装命令行工具，使其可以从终端调用。版本号随发布变化，本文不要求你得到某个固定数字。安装失败时，先读错误信息，不要重复执行一串不明命令。

随后进入你的练习目录再启动：

```powershell
Set-Location 'D:\Codex练习\hello-codex'
codex
```

按首次登录提示完成登录。也可以使用：

```powershell
codex login
codex login status
```

前一个命令启动登录流程，后一个查看当前登录状态。不要把登录信息文件上传到博客或 GitHub。退出认证可以使用 `codex logout`；它与关闭终端不是同一回事。缓存认证可能由多个 Codex 入口共用，退出后其他入口也可能需要重新登录。[命令行参考](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

CLI 内可以从 `/status` 查看会话状态，从 `/permissions` 查看权限设置；以当前版本的命令提示为准。更新 npm 版时再次执行 `npm install -g @openai/codex`。

### 第八步：可选——在 VS Code 中使用

已经使用 VS Code 的读者，可以通过 [Codex IDE 官方说明](https://learn.chatgpt.com/docs/codex/ide)提供的链接安装扩展，避免安装名称相似的第三方扩展。

安装后打开项目文件夹，进入 Codex 侧边栏并登录。若找不到侧边栏，官方文档给出的命令入口是 `Codex: Open Codex Sidebar`，可从命令面板搜索。

举例：你正在看 `index.html`，可以选中按钮相关代码，再让它解释按钮为什么没有响应。但仍要说清楚“先解释”“允许修改”或“仅检查”，不要让它猜你的意图。

## 实际应用：用 Codex 维护自己的博客

### 场景一：先摸清项目，再修改

```text
请先阅读当前 Hexo 项目的 package.json、_config.yml 和 README。
说明文章目录、主题配置位置、已有构建命令。
不要修改文件。发现不确定的地方请列出来，不要猜测。
```

这相当于让新同事先看说明书。相比一开始就要求“全面优化”，它更容易发现网站是 Hexo、Vite 还是其他结构，避免误用命令。

### 场景二：给任务加上明确的验收标准

```text
请新增一篇适合初学者的 Excel SUMIF 教程，保存为 Hexo Markdown 文章。
要包含学习目标、示例表格、逐步公式解释、常见错误、练习和答案。
用“部门报销金额汇总”作为贯穿案例，每个公式说明各参数。
设置 title、date、categories、tags、description。
遵循现有分类和学习路线结构，不要修改其他文章。
完成后运行项目现有的构建与验证命令，明确列出检查结果。
```

这不是让 AI 凑字数，而是规定“读者看完能做什么”。如果发现它只解释了公式名称，可以继续要求：“请用表格中的第三行数据，演示条件为什么成立、金额怎样计入合计。”

### 场景三：先把报错说清楚

不建议只发“打不开”。更有用的描述是：

```text
我在 Windows PowerShell 中，项目目录为当前目录。
执行 npm run build 后失败，下面是完整错误及最后二十行日志。
预期是生成 public 目录；目前构建中断。
请先定位原因，再做最小修改；不要删除文章或重装全部依赖。
```

日志中若含密码、Token、个人身份信息，应先去除。提供报错原文通常比只截一个红色图标更便于排查。

### 场景四：本地检查和互联网发布要分开理解

`http://127.0.0.1:4000/` 里的 `127.0.0.1` 指当前电脑。本地服务停止、终端关闭或电脑关机后，这个地址就可能打不开。把它发给朋友，朋友访问的也是自己的电脑。

GitHub Pages 的公网地址由托管平台提供。发布时应明确仓库、分支、是否公开、使用哪条部署流程，并检查 Actions 和网页结果。可以这样下任务：

```text
请先检查本地构建，给出将上传的文件范围。
公开资料仅包含博客正文和已授权图片，排除 .env、登录凭据及私有资料。
然后按当前仓库现有的 GitHub Pages 工作流发布。
部署完成后检查线上文章链接，并报告实际检查结果。
```

“Git 能提交代码”“GitHub 已登录”“浏览器连接可用”是不同状态。扩大文件权限不能代替 GitHub 登录。如果需要登录或验证码，自己在受信任的登录页面完成，不要把密码粘贴到聊天里。

### 场景五：让长期规则写下来

可以在项目中使用 `AGENTS.md` 记录协作规则，例如“用中文说明”“沿用现有分类”“使用项目已有构建命令”“不能验证就明确说”。保持规则短、具体、与项目相关；它是工作说明，不是万能的权限授权文件。

技能和插件也各有用途：技能通常提供某类任务的做法，插件或连接器提供与外部服务交互的能力。安装了技能，并不意味着自动获得你的邮箱、GitHub 或浏览器账号权限。

## 常见问题与解决方法

### 1. 输入 codex 后提示“无法识别”

先确认你是否安装了 CLI。安装桌面客户端不代表一定有同名终端命令。

如果按 npm 方式装过，重开终端，再执行：

```powershell
Get-Command codex -ErrorAction SilentlyContinue
npm list -g @openai/codex --depth=0
npm config get prefix
```

第一行找命令；第二行查全局包；第三行看全局安装位置。没有包就先解决安装失败；有包但找不到命令，再核对 PATH。不要在不知道实际安装位置时，照抄一个别人的用户目录加进环境变量。

### 2. PowerShell 提示 npm.ps1 或 codex.ps1 不能运行

这通常涉及 PowerShell 脚本执行策略。对于 npm 安装方式，可以先尝试相应的 Windows 命令包装器：

```powershell
npm.cmd --version
npm.cmd install -g @openai/codex
codex.cmd --version
```

这些命令仍需要真实安装成功的 npm 和 Codex。不要为解决一次报错就把系统全局策略改成无限制；单位电脑还可能有组织策略，应按管理员要求处理。

### 3. 应用能打开，为什么不能修改文件

依次检查：是否进入 Codex 开发任务；是否打开正确项目目录；是否只允许读取；申请操作是否还在等待审批。把任务写成“请实际修改当前项目中的某文件，并给出差异”，然后观察文件面板是否变化。

某些能力还取决于环境和连接器。只在聊天中贴出 `D:\某目录`，并不能保证应用能访问它。

### 4. 为什么它看不到我在 Chrome 中打开的网页

浏览器里打开了网页，与 Codex 连接了那个浏览器，是两件事。先看当前环境是否提供浏览器工具、是否需要扩展或连接授权、是否选中了正确标签页。不要尝试通过分享密码保险箱内容解决连接问题。

### 5. 修改后网页还是旧的

先判断看的是本地预览还是公网地址，再检查：文件是否保存、构建是否成功、部署是否完成、页面是否需要刷新。公网 Actions 失败时，本地文件改了也不代表线上已经更新。

例如，在本地写完文章后，只执行了保存，没有推送到部署仓库，那么线上仍显示旧内容是正常现象。

### 6. 为什么会停下来请求批准

通常是当前操作超出了已有权限或需要确认。读清申请里的命令、目标路径和理由。如果是自己的项目构建，可以据实决定；如果是删除陌生目录或公开上传未经检查的文件，先让它解释影响。

权限适合按工作范围设置，不需要把所有任务都改成完全访问。审批方式可能由应用设置或组织策略管理，聊天中的一句要求不一定能更改它。

### 7. 回答看起来正确，为什么程序仍然失败

解释合理不等于代码已经运行通过。要求它给出执行命令、退出结果和未验证项目，再用你的实际输入检查。

例如，一个金额汇总程序必须试一试空表、零金额和小数；一个按钮必须真的点击。不要只看“完成”两个字。

### 8. 使用额度不够怎么办

查看应用提供的额度与恢复时间。把一次任务拆成“先阅读和定位，再修改，再验证”；提供明确目标与报错；避免没有新信息时反复要求从头全面重查。不同模型、任务复杂度和套餐规则可能影响消耗，不要把次数理解成固定不变的计量单位。

### 9. 哪些内容不能放进公开仓库

不要提交 `.env` 中的秘密、API Key、登录令牌、浏览器认证数据或 Codex 认证缓存。官方认证文档提到的认证文件和系统凭据存储都属于敏感信息。截图也要检查账号隐私和内部路径。

发现密钥已经公开时，仅删除文件通常不够，应先在对应平台撤销或轮换密钥，再处理仓库历史。

## 练习与参考答案

### 练习一：把模糊任务变清楚

原始要求：“帮我优化博客。”请补充至少四项能检查的条件。

**参考答案：**只修改文章页样式；手机宽度下代码块不挤出页面；正文宽度保持适合阅读；保留深浅色模式；运行现有构建；说明哪些浏览器检查实际执行。是否好看仍有主观因素，但这些条件已经可以逐项验证。

### 练习二：找出计数器任务的验收点

请写出三条不依赖代码知识的检查。

**参考答案：**初始数字为 0；点击三次显示 3；重置恢复 0。还可以补充手机窗口下按钮不遮挡文字。

### 练习三：区分环境问题与权限问题

终端提示“找不到 npm”，你应该开放全部文件权限吗？

**参考答案：**先检查 Node.js/npm 是否安装、终端是否重开、命令位置是否在 PATH。扩大访问权限通常不会把一个未安装的程序变出来。

### 练习四：检查一次发布是否完成

AI 说文章写好了，但线上搜不到。你会检查哪些环节？

**参考答案：**Markdown 是否存在并有正确 Front-matter；本地构建是否包含文章；搜索索引是否生成；代码是否上传到正确仓库和分支；部署是否成功；浏览器访问的是不是最新公网地址。不要直接重装整个博客。

## 知识总结

使用 Codex 的关键不是记住一堆按钮，而是建立一个稳定流程：**选对项目 → 说明目标和边界 → 允许必要操作 → 查看修改 → 运行检查 → 再发布。**

初学者先用桌面入口完成一个小练习；需要终端或编辑器工作流时，再安装 CLI 或扩展。遇到问题时，先区分账号、工具安装、项目路径、权限、网络和部署这几类原因，每次只解决一个明确问题。
