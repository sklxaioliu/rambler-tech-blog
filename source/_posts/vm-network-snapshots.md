## 学习目标

能按用途选择网络模式，使用地址与路由信息排错，创建和恢复实验快照，并理解快照的局限。实验对象为你自己创建的 Ubuntu 或 Windows 客户机。

<!-- beginner-revision-2026-10-22 -->

## 先用一个例子理解

### 三种网络模式像三种接入方式

NAT像由宿主统一帮客户机对外通信；桥接像让客户机直接接入真实局域网；仅主机像先建一条实验内部道路，默认不直接提供外网。这些比喻只解释用途，实际可达范围还受路由、防火墙等影响。

快照像一条可以返回的游戏存档，但它依赖原来的游戏文件；独立备份更像把完整存档复制到另一块安全介质。删除快照通常是合并状态，不是“回到过去”，两个动作不能弄反。

## 基础知识：三种常见模式

| 模式 | 通常用途 | 需要留意 |
| --- | --- | --- |
| NAT | 客户机共享宿主外网连接 | 外部主动访问通常需要额外端口转发；不代表绝对隔离 |
| 桥接 | 让客户机接入真实局域网 | 受局域网 DHCP、Wi-Fi、认证与访问策略影响 |
| 仅主机 | 宿主与实验机、同虚拟网段实验机通信 | 默认不直接提供外网；额外路由可改变这一点 |

快照保存某个时间点的虚拟机状态。是否保存内存取决于创建时选择与产品支持。快照依赖基础磁盘和增量文件，不能替代独立备份。删除快照通常是合并状态，不是恢复到该时刻。

## 操作步骤：先用 NAT 建立基线

1. 保存客户机工作。按软件支持的方式关机并进入设置，核对网卡已连接，选择 NAT。
2. 开机后查看地址和默认路由。Windows 用 `ipconfig /all`，Ubuntu 用下面命令。
3. 记录默认网关与 DNS。不要把文档里的示例地址当成实际网关。

```bash
ip -br addr
ip route
resolvectl status
getent hosts example.com
```

4. 用 `ping` 测试你自己网络中允许探测的网关，再测试域名解析和 HTTPS。ICMP 被拦截时，ping 不通不能单独证明网络完全不通。
5. 如需桥接，只在有权接入的局域网中测试，并确认客户机获配了该网络允许的地址。

Windows 客户机也可检查应用端口：

```powershell
ipconfig /all
Resolve-DnsName example.com
Test-NetConnection example.com -Port 443
```

### 分步拆解：为什么这样操作

**先保存原网络配置。** 写下模式和客户机地址。一次只改一项，开机后先看地址、再看默认路由、最后看域名和端口，避免同时修改五处后不知道哪处有效。

**创建快照时写说明。** 名称可以是“网络修改前”，描述具体系统版本和网络模式。名称叫“快照1”过几天很难知道有什么用途。

**用一次性文件测试恢复。** 先创建快照，再在客户机家目录写snapshot-demo.txt，确认里面没有重要资料后恢复。文件消失可说明返回了早先状态，但宿主共享文件夹里的内容未必随之恢复。

**恢复前先备份要保留的改动。** 不把正在写的课程笔记当成一次性测试数据。

## 实际应用：试验前创建恢复点

先把文档保存到磁盘，关闭不必要应用，创建名为“网络修改前”的快照，并描述系统版本、网络模式和日期。接着在 Ubuntu 创建文件：

```bash
printf '快照后的实验内容\n' > ~/snapshot-demo.txt
cat ~/snapshot-demo.txt
```

确认这个文件只是一次性实验数据，再恢复刚才的快照。恢复会丢弃快照之后的客户机改动，文件应回到快照时的状态；实际结果取决于文件存储位置，共享文件夹中的宿主文件不受客户机快照保护。

恢复前应另外保存需要保留的内容。不要长时间保留大量快照链；客户机关机后按产品文档做独立备份，并确保加密信息也能恢复。

## 常见问题与解决方法

- **169.254.x.x 地址**：通常表示未获得预期 DHCP 配置，检查虚拟网卡连接、虚拟 DHCP 与模式。
- **能连 IP 不能连域名**：重点检查 DNS，不急着重装虚拟化软件。
- **桥接连不上 Wi-Fi**：可能与无线网策略、认证或驱动有关，学习上网可先使用 NAT。
- **快照文件越来越大**：增量持续记录修改。清理前做备份并预留合并所需空间，不手动删除磁盘链文件。

## 练习与参考答案

**练习：** 客户机ping不通网站，却能打开网页，是否一定网络故障？不一定，对方可能不响应ICMP，应结合DNS与TCP端口判断。

**练习：** 要撤回快照后的实验改动，应点恢复还是删除快照？目标是恢复到快照。删除快照不是同一个行为，操作前必须核对提示。

## 知识总结

先判断地址，再判断路由、DNS 与应用端口；快照用于短期实验恢复，备份用于独立保留成果。两者各有用途。
