## 学习目标

分清数据、数据库、数据库管理系统和业务应用；知道关系型与非关系型数据库的区别；能够解释 MySQL、SQL 和客户端之间的关系。先把这些角色认清，后面安装软件时才不会把“装了一个管理界面”误当成“数据库服务已经启动”。

## 先用一个例子理解

一家小店用表格记订单：订单号、商品、数量、金额。每一笔订单里的具体值是数据；把许多记录有组织地存起来，就形成了数据集合。店员使用的下单页面是业务应用；页面背后负责保存和查询记录的软件，可以是 MySQL 这样的数据库管理系统。

例如顾客询问订单 1001 是否发货，页面会把请求交给后端，后端向 MySQL 发出查询，再把结果显示出来。顾客不需要直接操作数据库，正如点餐的人不需要进入后厨。

## 基础知识

| 名称 | 可以怎样理解 | 本例中的角色 |
| --- | --- | --- |
| 数据 Data | 可以记录和处理的事实 | 订单号 1001、金额 68.50 |
| 数据库 DB | 按结构组织的数据集合 | 学习库中的订单与商品表 |
| 数据库管理系统 DBMS | 定义、保存、查询和控制数据的软件 | MySQL Server |
| 数据库应用 | 面向用户完成业务的程序 | 订单管理网页 |
| SQL | 向关系型数据库表达操作意图的语言 | 查询订单的语句 |

关系型数据库把相关数据组织成表。表有列和行：列规定要记录哪些属性，一行表示一条记录。`employee_id` 这一列放编号，编号 1 对应的一整行记录一位员工。主键用来区分行，外键用来建立表之间的参照关系。

非关系型数据库包括键值、文档、图等不同模型。例如文档数据库可以保存结构不同的文档，键值系统可以按键快速取得缓存。它们不是“没有结构”，也不是天然比关系型数据库快。选择要看访问方式、事务要求、数据关系和维护能力。

MySQL 是关系型数据库管理系统的一种。SQL 还可以用于其他数据库，但不同产品在数据类型、函数和分页语法上有差异。学会 SQL 的基本思路，不等于每条 MySQL 语句都能原样放到其他系统中。

## 图示详解

![数据、数据库与应用的关系](/img/mysql-guide/01.svg)

从左向右看，业务应用负责接收用户动作，MySQL 负责处理存取请求，数据库里的表负责承载结构化记录。箭头表示请求和结果的传递，不表示三个程序都需要分别安装。数据库是 MySQL 管理的对象，不是另一个叫“DB”的独立软件。

图中的“订单号 1001”是具体数据，“订单表”是组织这些数据的结构。这个层次区别，也能帮助你理解“删除一条订单”和“删除整张订单表”为什么影响不同。

## 操作步骤

先认识下面两种界面，再安装下一篇需要的软件：

1. PowerShell 是 Windows 命令环境，可以启动客户端程序。
2. `mysql>` 是连接成功后出现的 SQL 输入提示符，用来接收 SQL。
3. 管理工具的“新建连接”只是建立访问配置，真正的数据仍然由服务器管理。

连接成功后可以查看当前环境：

```sql
SELECT VERSION() AS mysql_version;
SELECT DATABASE() AS current_database;
SHOW DATABASES;
```

第一条返回服务器版本；第二条若返回 `NULL`，通常只是还没有选择默认数据库；第三条列出当前账号有权看到的数据库。不要因为列表里没有某个库，就断定服务器没有这个库，账号权限也会影响可见范围。

## 实际应用

如果同事说“我的数据库打不开”，先把问题分解：是网页打不开、客户端无法连接，还是某张表查不到？网页打不开要检查应用；连接被拒绝要检查服务和地址；查询报表不存在则检查库名、表名和权限。角色分清以后，排查方向会明确很多。

小项目也不需要一开始就换很多数据库。先用一套关系型数据库把数据结构、增删改查和事务理解清楚，比只记产品名称更有帮助。

## 易错点

SQL 不是 MySQL 的缩写；客户端不是服务器；数据库文件也不是普通电子表格。关系型数据库可以有多张表，表之间通过键建立关系，而不是把所有业务都塞进一张超宽的表。

MySQL 有社区版和商业产品，也有不同发布系列。学习时先选定一个基线版本，再查对应文档。本系列使用 MySQL 8.4 的语法说明，不沿用旧教材里“最新版本”的年代判断。
