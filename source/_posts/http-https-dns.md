## 学习目标

能描述浏览网页时名称解析、连接建立、TLS 与 HTTP 的关系，会使用 curl 与浏览器网络面板观察请求，不把 HTTPS 小锁误认为网站绝对可信。

## 先用一个例子理解

### DNS查地址，TLS核对身份并保护通道，HTTP交换内容

像去银行办事：先查营业网点地址，再确认自己确实进入可信网点，最后递交业务单。DNS、TLS、HTTP各自解决不同问题，不能用“地址查到了”证明网站内容可信。

HTTP请求像一张写明“我要什么”的单据，响应带状态码和内容。200常表示请求成功处理，404表示资源未找到，500表示服务端处理失败；它们不是下载进度。

缓存像通讯录里的旧副本，能减少重复询问，但地址改变后旧副本不一定马上失效。HTTPS保护传输，不保证网站经营者或文章本身可信。

## 基础知识：三种不同职责

DNS 是分布式命名系统。查询可以命中浏览器、操作系统或递归解析器缓存；未命中时解析器可能依次向相关服务器询问。A 与 AAAA 记录分别对应 IPv4、IPv6，CNAME 表示别名，TTL 影响缓存时间。因此修改 DNS 不会立即让所有用户看到新值。

HTTP 是请求与响应协议。客户端发送方法、目标和头部，服务端返回状态码、头部及可能的正文。GET 常用于读取，POST 常用于提交；是否可安全重试还取决于方法语义和业务设计。HTTP 的“无状态”不等于网站不能登录，Cookie 和服务器会话可在请求之间关联用户。

HTTPS 使用 TLS 保护 HTTP 传输中的机密性与完整性，并通过证书等机制认证服务器身份。它不保证网站内容真实、不含恶意行为。常见 HTTP/1.1、HTTP/2 经 TCP + TLS，HTTP/3 则基于 QUIC，不能说所有 HTTPS 都先进行 TCP 三次握手。

## 操作步骤：观察一次访问

在 Windows PowerShell 执行：

```powershell
Resolve-DnsName example.com
curl.exe -I https://example.com
curl.exe -L -o NUL -s -w "HTTP状态=%{http_code}\n总时间=%{time_total}s\n" https://example.com
```

第一条查看解析；第二条使用 HEAD 获取响应头；第三条跟随重定向并把正文丢弃，显示最后状态和耗时。部分网站不支持 HEAD，这不等于 GET 一定不可用。示例网站响应和网络耗时以实际结果为准，本教程没有虚构固定测速值。

然后在浏览器打开开发者工具的 Network 面板，刷新页面，选中文档请求，查看方法、状态码、响应头和 Timing。页面可能继续请求 CSS、脚本和图片，“一次访问”通常包含多条 HTTP 请求。

### 分步拆解：为什么这样操作

**先查域名记录。** Resolve-DnsName显示解析结果；可能命中缓存，不代表每次都问遍全球DNS服务器。

**再读响应头。** curl -I使用HEAD请求；状态码后面的头部可以包含重定向位置、内容类型、缓存信息。不要把命令输出里的每个数字都当作速度。

**跟随重定向再比较。** -L允许跟随跳转，最终状态与第一个站点返回的301可能不同。网址跳到哪里也需要看清。

**在浏览器Network面板验证。** 先打开面板再刷新，点主文档请求，看Headers与Timing。图片、CSS、脚本是另外的请求，一个页面并非只有一次HTTP通信。

## 实际应用：部署博客后检查

| 观察 | 可以说明什么 | 下一步 |
| --- | --- | --- |
| 301/302 | 服务端要求跳转 | 检查 Location 与最终地址 |
| 200 | 本次 HTTP 请求成功 | 继续确认内容是否正确 |
| 404 | 请求资源未找到 | 检查路径、大小写与部署产物 |
| 500 | 服务端处理失败 | 查看对应服务日志 |
| 证书错误 | 身份验证链路异常 | 检查域名、系统时间与证书配置 |

静态博客的子路径尤其容易出错。如果站点部署到 `/blog/` 而资源仍请求 `/css/...`，可能返回 404。应使用正确 root 配置并重新构建，不能只修改页面标题。修改 DNS 后等待 TTL 并检查权威记录，而不是反复清空所有配置。

## 常见问题与解决方法

- **解析成功但打不开**：继续检查端口、代理、证书与应用响应。DNS 成功只完成其中一环。
- **HTTP 跳 HTTPS 一直循环**：检查托管平台、反向代理和应用重定向是否互相冲突。
- **证书过期能否忽略**：应修复证书与时间配置，不把关闭验证写进日常访问脚本。
- **清缓存仍看到旧内容**：可能来自 CDN、浏览器缓存、Service Worker 或尚未更新的部署，按请求头与实际产物逐项判断。

## 练习与参考答案

**练习：** 网站返回404，能证明DNS一定完全故障吗？通常不能；能收到目标HTTP响应，说明已到达某个HTTP服务，应重点检查资源路径与部署。

**练习：** 修改域名后朋友仍看到旧站，先做什么？检查解析记录、TTL和缓存，再核对访问地址；不要反复随机修改全部设置。

## 知识总结

DNS 解决名称，HTTP 组织内容交换，TLS 保护传输。观察请求和响应，比只看页面是否“转圈”更能说明问题。

练习：打开自己的本地博客，找到主文档和 CSS 的请求，记录状态码。localhost 的 HTTP 开发预览与正式站 HTTPS 是不同环境。
